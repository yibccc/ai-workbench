# Private Current Resumes

## 1. Scope / Trigger

Use this contract for ResumeController/Service/Persistence/Mapper, V19, Markdown validation, private original reads and recovery. A resume belongs to an account, independently of community posts. Interview creation copies text; historical sessions never retain an original-object reference.

## 2. Signatures

- GET /api/me/resume -> Current(exists,version,markdownText,sourceKind,originalFile{id,fileName,size,sha256}).
- PUT /api/me/resume {mode:EDIT_CURRENT|PASTE,markdownText,expectedVersion,requestId} -> Receipt(requestId,operation,state,resultVersion,objectId,safeFailureCode).
- POST /api/me/resume/import: exactly multipart file,markdownText,expectedVersion,requestId.
- DELETE /api/me/resume?expectedVersion=<integer>&requestId=<UUID> -> Receipt.
- GET/HEAD /api/me/resume/original -> authenticated original bytes, never a provider URL.
- POST /api/me/resume/recover and /cleanup -> Maintenance(version,results[{objectId,state,safeFailureCode}]).
- ResumePersistenceService.snapshotForInterview(UUID owner,long expectedVersion) -> Snapshot(exists,version,markdownText,contentSha256), transaction propagation MANDATORY.
- V19: user_resumes(user_id PK,version,nullable markdown_text/source_kind/current_object_id,content_sha256), resume_objects and resume_write_receipts. Same-owner composite foreign keys protect pointers and receipts.

## 3. Contracts

GET is pure read. No singleton row means exists=false/version=0; the first write safely creates the row. An empty saved string is exists=true. Delete clears text/source/pointer/hash and increments version without deleting the singleton; never reset to zero and permit an old request through an ABA cycle.

EDIT_CURRENT binds the server current version and retains the original source/pointer. Only an explicit PASTE replacement, new import or delete changes the original reference. PASTE creates no pseudo-file. File selection first loads the editor; saving imports the immutable original File plus the independently edited final text. Original SHA/bytes and final-text SHA are different facts.

Only .md originals are accepted. Reuse AttachmentValidator.stage and ValidatedAttachment for bounded actual-byte count, SHA and strict UTF-8/control validation; MarkdownText is shared with the existing worker, preserving image/PDF rules. Raw originals are at most 1,048,576 bytes; decoded original and final text are each at most 20,000 Unicode code points. Strip only the leading encoding BOM from the decoded original, preserve original bytes and final text, and permit empty MD. Reject malformed UTF-8/unpaired surrogates/NUL/forbidden controls; CR/LF/TAB remain valid. The byte gate's inclusive 1MiB does not exempt the separate 20k body gate.

Mode names and JSON version tokens are exact in ResumeJson. Do not use Jackson numeric enum ordinals or float/string-to-long coercion. Frontend uses Array.from(text).length; backend codePointCount; do not use maxLength to truncate.

Authenticated userId binds every query/write/association; ADMIN has no bypass. Lock account -> current -> ordered objects -> receipt. Snapshot creation uses the caller's short transaction, freezes owner/current version/text/hash, and fails on a stale version. Return 404 for foreign resources before revealing state/version.

Canonical request fingerprint includes operation/mode/version/exact final text and original SHA/size when importing. Same owner/operation/requestId+payload replays the fixed minimal outcome before stale-version checks; changed payload conflicts. Replay never authorizes a replaced original or rebinds old current data.

Import uses short reserve transaction -> storage put outside transaction -> short confirmation. A valid current version, token, UPLOADING state and unexpired lease are required. Apply current/receipt subwrites first; the final READY CAS checks lease_expires_at > clock_timestamp(), and zero rows throws so the whole transaction rolls back. A separate failure transaction preserves FAILED receipt/key for cleanup. A transaction-start timestamp or only a pre-write Java time check cannot prove execution rights after a slow database trigger.

Object keys are interview/resumes/<userId>/<objectId>.md, generated by the server and immutable. Reads authorize current owner/pointer/READY before opening or emitting metadata. Use bounded streaming, attachment filename, nosniff, no-store/private and Accept-Ranges:none; authorized Range/conditions return full200. Close provider streams on completion/disconnect.

Replacement/delete make unreferenced originals unreadable immediately, then durable cleanup rechecks references, active IO and uncertain upload deadlines. A failed/timed-out put is not proof that the server finished writing; keep io_uncertain/key/deadline and a tombstone for repeated compensation. Late put during DELETING/DELETED moves to DELETE_FAILED so an old cleanup cannot falsely finalize permanent deletion. Startup plus 30s scans recover expired operations; this is orphan compensation, not day-based business deletion or model retry.

## 4. Validation & Error Matrix

| Condition | Result |
|---|---|
| Anonymous/foreign original | 401/404; no filename/size/bytes |
| Missing/unknown/numeric mode or noninteger JSON version | 400; no current mutation |
| Bad UTF-8/control/surrogate, wrong extension/parts | 400; original and editor preserved |
| Original actual bytes >1MiB or text >20k code points | 413/400 respectively; no truncation/READY/swap |
| Stale version / same requestId changed payload | 409; current unchanged |
| Put/confirmation/expired terminal lease | Safe failure, old current preserved, durable failed candidate |
| Cleanup IO failure or uncertain late put | Unreadable retryable cleanup state; no false physical-delete success |

## 5. Good / Base / Bad Cases

Good: import A, edit its final text while preserving A's bytes, create session1, then replace/delete current; session1 keeps its frozen text and only an unreferenced original is cleaned. Base: empty MD is valid, while a user with no current can create a general interview. Bad: attach originals to a community post, overwrite immutable keys, reset version after delete, trust receipt as current, mark READY before all subwrites without a final lease fence, or erase the only cleanup key after an uncertain put.

## 6. Tests Required

Use real isolated PG/Redis/RustFS and A/B/ADMIN/anonymous HTTP+CSRF. Assert owner 404/cache/GET+HEAD+Range, raw BOM/SHA, both original/final 20k emoji limits, byte stage 1MiB/+1 and composite API rejection, empty/null distinction, concurrent first writes/import CAS, exact request replay, deletion ABA and MANDATORY snapshot. Force put/DB/cleanup failures and late DELETING completion. Kill an actual UPLOADING JVM and recover from a new JVM. Delay a current subwrite across the lease and assert zero READY/current/version change plus a FAILED receipt. Verify existing AttachmentValidation tests after sharing MarkdownText.

## 7. Wrong vs Correct

Wrong: check a Java timestamp once, set READY, then perform slow current writes. Correct: retain short locks and make READY the last token/owner/state/clock_timestamp lease CAS; any failure rolls back current and receipt, followed by independent failed-candidate compensation. Wrong: editing an imported current implies PASTE. Correct: EDIT_CURRENT preserves its server-bound original; explicit PASTE chooses a different source.
