# 前端工作区单屏布局

## Goal

让工作记录、待办任务、工作汇报和项目管理各占一个浏览器视口；页面本身不发生纵向滚动。各列表固定每页 5 条，并把空间留给内容。确有溢出的区域分别滚动，能放下的区域不显示滚动条。

## Background

- `frontend/src/components/layout/AppShell.tsx` 统一渲染四个工作区的导航、顶栏和主内容。
- `frontend/src/styles.css` 中 `.app-shell` 只有 `min-height: 100vh`，`.main-content` 不限制高度；正文会撑高文档。
- 四个工作区有较长的列表、表单或报告来源；记录、待办、项目和报告已各自使用分页。
- 在窄屏（≤760px）时，导航移到页面顶部；现有弹窗和编辑抽屉已有独立的最大高度及纵向滚动。
- `frontend/e2e/workbench.spec.ts` 已覆盖多种宽度的横向溢出，但未约束页面级纵向滚动。
- `backend/src/main/java/com/aiworkbench/common/PageResponse.java` 当前仅允许每页 10、20、50 条；前端各分页当前默认为 20 条，并显示每页条数选择器。

## Requirements

- R1. 四个工作区在桌面和窄屏宽度下，浏览器文档高度不超过当前可见视口高度。
- R2. 导航、顶栏、当前工作区标题及简短操作控件在视口内常驻，不因内容增多而被推到视口之外。常驻控件包括记录日期、待办新建及筛选、项目创建及搜索、汇报类型及生成/版本选择。
- R3. 超出视口的正文、列表、表单及分页控件仍可通过滚动或键盘访问；不得裁切内容。
- R4. 原有导航、分页、报告草稿保留、弹窗和编辑抽屉交互保持可用。
- R5. 窄屏、小高度窗口以及浏览器缩放下，常驻控件和下方内容区都仍可访问，不出现无法触达的操作或水平溢出。
- R6. 所有前端分页列表固定每页 5 条数据，包括记录、待办、项目、日报/周报历史和报告事实来源；不再显示每页条数选择器。后端分页接口接受 5 条，同时保留现有 10、20、50 条请求的兼容性；报告生成仍使用完整事实集合。
- R7. 主内容整体向左上适度靠拢，减少无效留白，并在不同宽度下保持舒适的内容边距。
- R8. 滚动条仅在所属区域内容溢出时出现，外观细致、低对比；报告正文与事实来源各自独立滚动，事实来源翻页控件保持可访问。列表 5 条能装下时不显示该列表的滚动条。
- R9. 每个带分页的卡片把分页控件固定在卡片底部；滚动数据时分页按钮仍可直接点击。适用记录、待办、项目、日报/周报历史和报告事实来源。分页不遮挡最后一条数据。
- R10. 工作汇报页把“日报 / 周报”切换按钮移到页标题右侧，替换“生成内容可核对”；移除“选日期 → 生成版本 → 编辑并保存”提示。切换时的未保存标记和草稿保留行为继续有效。
- R11. 周报编辑区域收紧标题、日期、生成/版本控件的竖向间距，为下方正文与事实来源留出更多高度；桌面与窄屏控件均可访问。
- R12. 在成功生成的周报编辑区，AI 周报正文与“用户补充（不会附加 AI 来源）”分别放在左右并列的两个卡片；窄屏时顺序纵向排列。把“保存 AI 正文”和“复制组合周报”放在右侧用户补充卡片最上方，且操作仍针对原有的正确内容；“独立保存用户补充”和事实来源继续可用。
- R13. 日报、周报的顶部操作控件在宽屏按“历史版本 → 生成日/周报 → 选择日期”从左到右排列：历史版本靠中间，生成按钮位于日期左边。窄屏允许换行或纵排，但保持控件顺序和完整可达。
- R14. 周报成功态的 AI 正文与用户补充两张卡片应让顶部操作与底部保存按钮在正常桌面视口内直接可见；长文本在输入框内滚动，不裁切内容或挡住按钮。卡片在后续 R21 中可利用剩余高度伸展，事实来源区域仍可访问。
- R15. 操作后的临时成功、信息和错误提示使用统一的悬浮提示框，出现 5 秒后自动消失，并允许在 5 秒内手动关闭；持续性的表单校验、未保存提醒和报告失败状态仍应保持可见。
- R16. 待办页宽屏时把“待处理 / 已完成 / 全部任务”与项目、优先级、截止日期三个筛选排在同一行；空间不足时换行，所有控件仍可访问。
- R17. 工作汇报历史分页紧跟报告正文及编辑说明，减少两者之间的空白；日报和周报均保持事实来源区的独立滚动与分页可用。
- R18. 日报/周报“核对本版本来源”卡片在少量来源时不出现内外两层多余滚动条，来源分页始终能在卡片底部看到；来源内容确实超过卡片可用高度时，只在来源列表内部按需滚动，长内容和分页均可到达。短窗口仍保留可访问的外层滚动路径。
- R19. 日报编辑的“保存正文”“复制正文”操作移到正文输入框上方，并与周报编辑卡片的顶部操作保持一致的可见性和样式；长正文仍在输入框内滚动，原有保存与复制语义不变。
- R20. 日报成功态把“删除此版本”“保存正文”“复制正文”三个按钮集中放在“已生成 · 版本 N · N 个冻结来源”信息右侧，宽度不足时允许换行；按钮仍分别执行原有删除确认、保存和复制操作。
- R21. 日报和周报在桌面成功态利用历史分页下方原有的大块空白，拉高上方正文编辑框及来源卡片，让历史分页靠近卡片底部；编辑说明仍紧邻分页上方，长正文在输入框内滚动，来源列表长内容内部滚动。窄屏和矮窗口仍能到达编辑操作、来源分页及历史分页。

## Acceptance Criteria

- [x] AC1（R1、R2）：在四个工作区，桌面与手机尺寸的文档没有页面级纵向滚动；导航、顶栏、工作区标题和各页简短操作控件保持在视口内。
- [x] AC2（R3）：当内容超过正文可见高度时，用户能滚动到最后一项及分页/底部操作。
- [x] AC3（R4）：切换工作区、记录输入、待办操作、报告编辑、项目管理和弹窗/抽屉的现有行为不受布局限制。
- [x] AC4（R5）：短视口与窄屏上，常驻控件和下方内容区都保有可用的访问路径，没有被固定容器遮住且无法触达的控件，也没有水平溢出。
- [x] AC5（R6）：前端各分页请求均使用 `size=5`，最多展示 5 条；无每页条数选择器。后端允许 `size=5` 且旧规格仍有效；周报生成仍引用完整来源。
- [x] AC6（R7）：桌面内容区相对上一版向左上靠拢，宽屏留白减少；手机宽度没有横向溢出。
- [x] AC7（R8）：5 条短内容能完整显示时无多余滚动条；长内容需滚动时滚动条细且不预留常驻宽槽。日报/周报的正文和事实来源能独立滚动并到达各自底部及来源分页。
- [x] AC8（R9）：在各带分页卡片中，滚动数据到中间或末尾时分页始终显示在卡片底部；上一页/下一页可点击，最后一条数据无遮挡。
- [x] AC9（R10）：汇报页标题右侧显示日报/周报切换按钮，不再显示“生成内容可核对”与流程提示；未保存标记和切换草稿保持正确。
- [x] AC10（R11）：周报编辑控件区较前一版更紧凑，下方正文/来源可见高度增加；在手机或矮窗口没有被裁切的控件。
- [x] AC11（R12）：桌面周报的 AI 正文卡片在左、用户补充卡片在右；两个指定按钮位于右卡顶部并可直接点击。手机上两卡上下排列，输入、保存 AI、复制组合周报、独立保存补充和来源核对均可访问，草稿与保存语义不变。
- [x] AC12（R13）：日报和周报宽屏操作行中，历史版本位于生成按钮左边且接近内容中部，日期位于生成按钮右边；窄屏无横向溢出，生成、选历史版本和改日期仍可用。
- [x] AC13（R14）：周报 AI 正文及用户补充输入框可独立滚动并读到全文；1440×900 且有状态/未保存提示时，右卡顶部按钮与“独立保存用户补充”均完整显示、无需先滚动外层容器，事实来源仍可点击。
- [x] AC14（R15）：待办重开等操作提示以统一悬浮提示框显示，5 秒后消失，5 秒内可关闭；不同页面连续提示会正确重置计时。
- [x] AC15（R16）：宽屏待办状态及三个筛选同处一行，窄屏仍无横向溢出且可操作。
- [x] AC16（R17）：周报截图所示编辑说明下方即为历史页码，日报同理；报告正文和来源的长内容、来源分页仍可到达。
- [x] AC17（R18）：桌面少量来源时没有截图中的双滚动条，来源分页在卡片底部可见；超过列表可用高度时来源列表按需滚动，分页位置不随来源行滚走；窄屏与短窗口可到达全部内容。
- [x] AC18（R19）：日报成功态进入编辑区后，无需滚过正文即可看到保存与复制按钮；长正文仍可读写，保存及复制内容正确，窄屏无水平溢出。
- [x] AC19（R20）：桌面日报三个按钮与版本/来源信息位于同一行并在其右侧；窄屏全部可达、不横向溢出；删除确认、保存正文、复制正文行为保持正确。
- [x] AC20（R21）：桌面日报/周报成功态的正文编辑区和来源卡片填充历史分页上方的可用高度，不再在历史分页下留下大块空白；有编辑说明时仍靠近历史分页。正文、来源、两个分页及操作在桌面、窄屏、短窗口都可访问。

## Out of Scope

- 不改变分页返回结构、业务数据和既有 10/20/50 条接口兼容性。
- 不重做四个工作区的信息层级或视觉样式。
