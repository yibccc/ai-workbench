# 技术设计

## 2026-09-21 已授权架构及分页重构

最新用户指令覆盖本文历史功能分包约束。后端调整为controller → service接口 → service.impl → mapper；dto/<业务>、entity/<业务>、enums、exception、common、config分类保存。Mapper XML统一resources/mapper，同步namespace/resultMap与测试引用；Flyway历史迁移保持不变。Input/Report编排与持久化继续是不同Spring Bean，事务不能因拆接口退化为自调用。

分页使用与Boot3兼容且锁定版本的PageHelper。API page仍从0开始，内部page+1；size仍10/20/50。reasonable=false保证越界空页，分页范围内只允许目标Mapper查询；映射DTO前先保存PageInfo总数，finally清理ThreadLocal，不能影响报告全量来源取数、重复查询和异步线程。SQL移除重复手工LIMIT/OFFSET与分页COUNT；默认排序保持created_at DESC,id DESC。

前端按features/{capture,projects,records,tasks,reports}、components、api、hooks、utils拆分；通用分页组件区分禁用末页与真正loading，禁用使用not-allowed，等待仅用于实际请求。核对请求页号、总页数、页面重置和迟到响应，不仅修改CSS。保留折叠草稿、WebSocket与无定时生成。

- 不引入 DDD；D9 以跨功能回归、浏览器测试和阻断修复为主，继续在现有功能包内修复问题。
- 后端关键用例在 PostgreSQL 环境运行，不用内存数据库替代事务与约束行为。
- 测试使用可控时钟，避免依赖运行当天和自然周。
- 前端端到端测试覆盖浏览器可观察行为；真实 API 调用与离线回归分开记录。
- 验收日志迁移到本任务 `research/acceptance-log.md`。
- 每个真实模型测试场景最多允许 3 次付费调用；每次记录场景、模型、耗时、结果和是否消耗重试额度，禁止无限自动重试。
- 浏览器自动化结果与用户真实体验反馈分开记录；用户未提供的体验结论必须标为待反馈。

## 用户反馈修订设计（已实施，替代此前定时生成建议）

### 1. 页面结构与交互

- 保留当前功能包和页面组件；新增共用 CollapsiblePanel、分页控件、可搜索 ProjectPicker、工作台日期工具和实时连接模块。
- 页面入口优先展示“一句话记录与安排”；其余日报、周报、待办、记录、项目管理具有可折叠标题。首次进入输入与待办展开，报告默认折叠；用户展开选择记入带版本的本地偏好。
- 折叠仅隐藏展示，不销毁正在运行的请求或未保存表单；标题展示数量/生成中/失败/未保存，关键状态可见。成功结果卡显示记录与待办的实际标题、数量和编辑按钮。
- 去除首页技术健康徽标及PostgreSQL等实现文案，保留诊断API供排障；正常使用不依赖健康检查请求成功。
- 项目选择器可搜索、限高、键盘选择；编辑已有归档项目时保留其标签，禁止新关联归档项目。迟到的搜索响应不能覆盖新查询。
- 默认每页20条，可选10/20/50。筛选变化回第一页；新建后回第一页；删除末页最后一项回到前一有效页。跳转AI生成条目应按ID加载/打开编辑，不依赖该条目恰好在当前分页DOM。

### 2. 分页与排序合同

- 提议新增兼容的分页查询入口：`GET /api/projects/page`、`/api/records/page`、`/api/tasks/page`、`/api/reports/page`，原数组API暂保留给既有调用；静态路径与`/{id}`映射需测试。
- 页号从0开始；响应 `{items,page,size,totalElements,totalPages}`，size上限50，参数越界400。沿用现有业务筛选；项目新增q搜索。
- 所有用户列表稳定按`created_at DESC, id DESC`，COUNT与分页使用相同筛选。报告历史摘要不携带全量正文/来源，选中后取详情；来源展示另分页，编号基于冻结顺序不因翻页变化。
- 来源取数和用户列表分页分开：报告生成不得只使用列表当前页，发生日期/自然周过滤不改成创建日期过滤。
- Offset分页允许在并发插入后页面边界变化；刷新/新增回第一页并重新取总数，不承诺跨多次请求数据库快照不变。

### 3. 手动日期与自然周

- 日报、周报各自保有选择状态，避免选周顺带改变正在编辑的工作记录日期。
- 日报默认上海当天，也可选历史日期。周报选择任意日期后归一到所在周一；UI显示“9月14日—9月20日（周一至周日）”，API仍存`[9月14日00:00,9月21日00:00)`。
- 今天星期与当前查看周期分开展示，避免查看历史周时被误认为当天。星期一至五常规颜色、周六橙色、周日红色，搭配文字，不能只靠颜色传达。
- 完全不新增定时、补生成和自动重试。删除18:00/23:00自动生成文案；按日期生成始终要用户点击。

### 4. WebSocket实时状态

- 新增同源`/ws/events`连接；浏览器共用一条连接，按input/report ID订阅。事件只通知已提交状态，形状拟定为`{eventId,kind,entityId,state,revision,occurredAt}`，不携带凭据和完整原文。
- 事务提交后推送input/report成功、失败、撤销和报告更新事件；推送失败不能回滚业务事务。客户端通过已有详情API拉取真实结果，刷新对应列表。
- 订阅完成后立即GET当前状态，解决“完成先于订阅”的竞态；断线指数退避重连，重连后批量核对本地保存的未完成ID；重复事件按ID/版本去重，迟到消息不回退状态。
- 持久保存有限的未完成实体ID，不存密钥/原文。页面刷新恢复跟踪；组件折叠不中断监听。WebSocket不可用时自动使用低频状态查询兜底，显示连接恢复中，无需用户手动刷新。
- 新结果不能覆盖未保存报告编辑稿；提示有更新/新版本并让用户选择。不同输入的结果按ID独立维护，防止旧请求污染最新结果卡。
- 服务端仅允许已配置的本机前端同源来源；开发代理支持WS，监听继续为回环。当前单后端实例使用进程内订阅广播，断线核对保证最终可见；不宣称跨节点消息广播。

### 5. 日报/周报失败诊断与修正

- 第一阶段增加脱敏错误码：MODEL_TIMEOUT、OUTPUT_TRUNCATED、INVALID_JSON、UNKNOWN_SOURCE、SOURCE_ROLE_MISMATCH、INVALID_BULLET等；保存阶段/计数/报告ID，普通日志不记录原文或模型完整响应。
- 根据失败可重现证据修复；当前无法从通用错误倒推143来源失败根因。周报统一称“周报/报告”，版本0展示“生成失败”而不是误导为已完成版本。
- 允许同一有效来源支撑不同要点；同一要点内重复ID规范化去重。所有ID仍必须属于本报告冻结快照且角色合法。来源合法不等于语义真实，成果/进展区分仍需提示、固定语义样本和真实验收。
- 提示使用短的本报告局部来源别名，服务端严格映射回冻结UUID；降低长UUID及重复字段对输出预算的消耗，不改变来源事实。
- 检查终止原因与JSON截断，不把截断误报为来源失败。控制输出要点与文本长度，不直接裁剪来源。
- 143条及长内容场景先用替身、解析夹具和提示预算测量。若单次请求无法覆盖全部来源，明确报容量限制并保留快照；多次付费分批汇总不默认开启，需单独设计来源覆盖与预算，不能借拆场景突破3次上限。

### 6. 测试数据清理

- 先从测试文件、验收日志与ID证据识别助手生成数据，名称包含test不是充分证据。生成只读清单：实体ID、归属证据、创建时间、依赖、可清理数量。
- 对确认且无用户后续编辑/关联的测试项目、测试待办，各选择最早的一半（floor(N/2)）。若不足以安全达到目标，停止有歧义部分并报告差额。
- 清理前导出选定行及必要依赖至不入Git的本地备份并检查可读性。任务优先复用软删除/完成记录失效规则；项目有非目标关联不得硬删，可归档隐藏并准确说明仍保留的数据。
- 不级联删除用户记录、报告快照或事件。每步用事务、版本/状态条件验证清单未变化；清理后报告精确数量及恢复路径。
- 清理发生在实现阶段，设计阶段不读取敏感内容或执行删除；回归数据持续保持隔离schema，修复造成历史数据污染的具体测试路径。

### 7. 风险与回滚

- 新增API采用兼容入口；模型、分页、WS独立回归，保留HTTP查询回退。
- 不改已应用V1—V9；仅在错误元数据或审计确需字段时追加迁移。
- 已有D9未提交实现保留。自动化验证通过不代表143来源真实语义已通过，付费验证按场景账本剩余额度执行。
