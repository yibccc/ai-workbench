# 子任务 PRD：业务数据归属与异步链路

父任务：`09-25-auth-isolation`。主责 FR-006～007 和 FR-013 的后端回归；父任务 `prd.md` 保留全部 AC 的唯一定义，`research/handoff/r1/acceptance.md` 是 TC 方法。依赖认证子任务给出不可变 `userId` 与 401/403 身份合同。

## 目标、范围与非目标

每个登录账号在既有项目、记录、待办、AI 输入和日报/周报中只看见、修改、关联和取材自己的数据。ADMIN 只拥有账号管理权限，业务内容依旧私有。新资源的归属来自服务端身份；异步 AI、恢复、重试、报告版本及通知沿原始请求 owner；同名项目、幂等 request ID、报告周期版本链按用户分隔。

范围覆盖列表/搜索/分页计数、详情、读写删、项目关联、任务事件、生成子项、撤销、报告来源/快照/版本、后台处理、错误优先级与回归。保留既有日期、乐观锁、软删除、事务及 UI 所依赖的业务语义。使用新迁移和经核实的空库起点，不认领旧测试数据。不引入 workspace/tenant、RLS、独立用户库、管理员跨用户业务读写或旧数据迁移功能。

## 可观察验收

- `AC-ISOLATION-001/003/005/006`：A、B、ADMIN 各自列表/计数/详情只含本人；他人 UUID 的读改删、跨用户关联均 404，且不能泄漏内容/状态或留下部分写入；伪造 owner 参数无效。见 TC-020～022。
- `AC-ISOLATION-002/007`：不同用户可同名项目及同 request ID，彼此不冲突或取回对方资源；同用户原唯一与幂等规则仍生效。见 TC-022/023。
- `AC-ISOLATION-004/008/009`：输入生成、失败重试/撤销/启动恢复、日报周报取材/来源/版本链/状态通知只归原用户；退出或他人登录不改变归属，报告不截断来源。见 TC-024/025。
- `AC-REGRESSION-001` 后端部分：原日期/上海时区、项目归档历史、待办版本及事务、AI token/租约、报告快照与版本、日报删除合同在每个 owner 内保持。见 TC-039。共享 `AC-ISOLATION-010` 的浏览器侧由前端子任务负责。

## 约束

当前 SQL 全局唯一与无 owner 查询是已核实的缺口。全部入口、Service、Mapper 和子/快照关联都要覆盖，不能只在 Controller 层过滤或只把 `user_id` 加到表而不改查询。测试必须使用真实 PostgreSQL 隔离 schema 和确定性 AI 替身；本轮规划不清真实数据库。
