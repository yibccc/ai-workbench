# 技术设计：专注与每日重复任务

状态：用户已在最终规划摘要之后批准执行；以下方案仍须通过实现和工程验收。对应 [prd.md](prd.md) 的 FR-001～005、AC-001～007；来源逐项核对见 [research/handoff-check.md](research/handoff-check.md)。

## 边界与数据流

沿用 Controller → Service 接口 → `service.impl` 事务 → MyBatis Mapper XML → PostgreSQL。账号及 CSRF 沿用现有 HTTP 客户端和 `CurrentUser`。专注计时的权威是服务端时间锚点、状态版本与持久区间；浏览器定时器仅用于显示和在前台请求状态转换。Redis 只承担现有登录会话，不成为计时正确性的依赖；不扩展为后台调度或离线闹钟。

工作台进入后显式提交“补齐今天”写命令，服务端按 `workbench.zone-id` 算当天，批量处理符合星期的模板。此命令可重试；读接口不隐式写库。前端从待办携带目标、taskId、projectId、默认时长进入 `#focus`，明确点击开始才提交会话。会话结束事务生成按日记录，既有记录查询和报告生成读该来源。

一项集成功能采用一个复杂 Trellis 任务：模板实例、会话、工作记录与页面之间共享所有权/日期/报告合同，拆成可独立归档的子任务会在验收时产生半成品；`implement.md` 明确内部顺序和阶段门禁。

## 持久化合同与迁移

当前最新迁移是 V14；规划新增 V15（若开工前出现更高版本，重新选择下一个版本，不编辑已发布迁移）。对象和字段名称以迁移实施时核对为准，职责与约束必须保留：

| 对象 | 最小数据和约束 |
|---|---|
| `focus_routines` | owner、title、project_id 可空、weekdays、default_duration_minutes、enabled、version、时间戳；项目外键约束同 owner。修改/停用不改历史实例。 |
| `todo_items` 扩展 | `routine_id`、`occurrence_date`、`default_focus_duration_minutes` 可空；数据库唯一 `(user_id,routine_id,occurrence_date)` 覆盖已软删实例，不使用 `deleted_at IS NULL` 的部分索引。实例保存生成时的标题、项目和默认时长快照，并经 TaskRow/Response 提供给待办入口；普通待办仍可空。`due_at` 不承载重复发生日期，原 `due=TODAY` 语义不变。 |
| `focus_sessions` | owner、可空 task/project 关联、目标与名称快照、目标净时长、提醒间隔、业务时区、阶段、版本、时间锚点、累计量、请求键、结束时间，以及提示控制者租约/代数；部分唯一索引保证每 owner 至多一个未结束会话。任务和项目关联须同 owner。V16 将已有待确认会话归一化，删除不再使用的待确认起止字段与 `RECOVERY_REQUIRED` 阶段。 |
| `focus_intervals` | session、单调序号、当前写入 `FOCUS/BREAK/PAUSE` 类型、服务器时间 `[start,end)`、确认状态；会话行锁与序号约束防重复。既有 `PENDING` 行只作为旧版历史审计保留，不参与新结算或新写入。 |
| `work_records` 扩展 | 新来源 `FOCUS_SESSION`，可空 sessionId、业务日期、净/休息毫秒数、分片起止、可选进展；约束 `(owner,session,date)` 唯一且仅对专注来源生效。V15 替换 V4 的来源及 task/source CHECK，允许专注带可选 `todo_id`，保持手工与任务完成旧约束。每个净投入大于零的日期写一条分片。 |

同 owner 外键、CHECK、唯一索引由真实 PostgreSQL 校验。`WorkRecordServiceImpl.requireManual` 目前阻止非手工记录通用修改/删除；保留此保护，专注进展用专用受控命令追加或修改，不开放通用时长编辑。`TaskServiceImpl.delete/reopen` 和 `WorkRecordMapper.invalidateTaskCompletion` 只失效 `TASK_COMPLETION`，继续保持专注历史。模板项目在生成前归档时不生成非法关联，返回该模板的可见阻塞信息；其他合法模板可照常补齐。已开始会话的合法历史项目/任务关联允许保留至结算，不自动抹除。

## 时间、状态与后台持续计时

- 统一内部时长精度为毫秒；数据库保存 `TIMESTAMPTZ` 时间点和整数毫秒累计值。使用服务器时钟计算 `[start,end)`，先按会话保存的 `workbench.zone-id` 切日，再聚合，最后才格式化秒/分钟。显示舍入不参与累计。
- 目标时长由用户输入正整数分钟，计划边界 1～480 分钟；提醒间隔 1～120 分钟，初始 10 分钟，休息固定 15 秒。边界作为交接包 DEC-009 留给本地的校验参数；实施时通过请求校验、数据库约束和边界测试固定，不从静态原型推导。
- 阶段为 `RUNNING / MICRO_BREAK / PAUSED / ENDED`，暂停保存来源阶段及剩余休息时间。累计净时间达到目标时优先结束，不再生成一次休息。跳过只计算已经实际经过的休息秒数；关闭提醒取消本段后续触发。
- 会话开始后由服务器时间锚点连续累计，切到其他标签/应用或设备睡眠不自动暂停；用户停工时需主动暂停或结束。前台与后台都尽量约每 20 秒发送一次无活动续期副作用的检查点，后台计时器可能被浏览器节流、冻结或在关闭页面后停止；下次命令按服务器时间补计至目标上限。该语义不检测人是否实际工作，睡眠时间也可能计入净专注。
- 检查点只推进当前已开始的 `FOCUS/BREAK/PAUSE`，不凭空触发微休息。页面可见且净时长到提醒阈值时才发条件 `BREAK_DUE` 开始 15 秒休息和提示；隐藏期间跨过多个阈值也只在重新可见时按当前净时长触发至多一个提示，不补造完成的休息或补播声音。目标净时长到期优先于休息；服务端检查点即使后台运行也可在目标到达时结算。
- 旧标签/延迟命令必须携带版本或转换序号，原子条件写入后才更新状态。正常前台提示的验证目标是发起转换到可见提示不超过 3 秒（在支持矩阵和已启用音频条件下）；后台、睡眠或关闭页不作准点承诺。系统时间调整不改变服务器已确认锚点。

## API、并发与音频控制

新增同源 `/api/focus/...`、`/api/focus/routines/...` 命令与查询，具体路由按现有 Controller 风格定名。读取模板、当前会话、今日汇总为纯读；补齐今天、模板读写/启停、开始、暂停/继续、可见时休息到点/跳过、关闭提醒、结束、补充进展为受 CSRF 保护的写命令。删除原 `/recover` 命令与确认 UI。开始含 owner 内唯一请求键；会话非终态唯一索引使并发不同目标最多一个成功，已有会话返回其状态或安全 409，不替换目标。结束先锁定 owner+session，重复结束读既有结算，不能重复分片或覆盖已提交进展；业务错误沿用安全 `ProblemDetail` 和 400/404/409。

每个提醒事件用 `(session,ordinal,phase)` 唯一逻辑键。账号内多个标签读取同一服务端会话，只有持有服务端条件租约和递增 fencing 代数的标签能尝试播放；租约与 20 秒检查点同路续期，60 秒过期后可接管。`BroadcastChannel`/本地通知只加快界面同步，不充当唯一性权威。浏览器无法证明扬声器实际发声，`AudioContext` 播放拒绝显示视觉提示；租约失效、后台节流可能漏响，不重放过期事件。自动检查点不调用 `/api/auth/activity`，换号或 401 时撤销旧控制者并清理账号级状态。

## 报告、前端与兼容

当前 `ReportMapper.xml` 的日/周候选都读取有效 `work_records`，但其快照只含 source/taskId/completionResult；`ReportSourcePrompt` 也仅传 source 状态与文本，日报生成器允许任意 RECORD 出现在成果或进展。新来源需在冻结快照、提示输入及来源展示中携带 sessionId、日期、净时长、可选 taskId/进展和“投入而非完成”语义。对同一任务的投入与完成在确定性来源整理阶段关联，生成提示明确不可把纯投入写成完成；验收用确定性模型替身和来源 ID 核对，既有版本的快照保持原样。专注结束本身不调用模型。

前端在 `navigation.ts` 增加 `focus`，保留原四项相对次序与 `records` 默认路由。`Workspace` 中增加 `RetainedView` 的 `FocusPage`，账号级状态和声音控制位于隐藏页面之外、账号根之内；`TasksPanel` 增加只带入上下文的开始入口；`AppShell` 顶栏容纳离页紧凑入口。`RecordsPage` 保留 date/mode/page 及原列表，只扩展来源渲染和数据刷新，不复用手工 `onSaved` 强制改日期。窄屏现为四列导航，需要验证五列下 320/390/760 像素的可达性和无横向溢出；页内滚动遵守现有单屏布局与焦点规则。UI 截图仅作层级和职责参考，具体颜色/页内标签不是产品冻结要求。

人工试用后用户直接要求把计时区左下快捷按钮改为 45 分钟并移除独立“声音与提示”卡片。计时页改为单主面板，点击开始时在同一用户手势中启用音频；刷新后会话仍可在主面板用紧凑按钮重新启用/试听，失败反馈留在主面板。任务或重复实例自带的默认时长不因快捷按钮改动而重写。

随后用户指定目标净时长输入框默认 45 分钟，并在点击/聚焦时显示 15/25/45/60 的快捷下拉，删除此前计划的下方 45 分钟按钮。输入框仍允许 1～480 分钟自定义；选项须可键盘访问，窄屏下拉不得被滚动容器遮挡。新无关联会话回到 45 分钟默认，待办/规则实例的保存时长仍优先带入。此条覆盖上一段关于快捷按钮的最终交互描述。

实施与验证矩阵：自动化先覆盖本仓库 Playwright Chromium 的桌面及 320/390 像素视口；Windows 本机可用的 Chrome/Edge 前台分别人工核验声音启用、拒绝、双标签和长时间切换应用后的连续计时；如实际测试设备睡眠，应观察其后继续计时而非恢复确认。按 README 的 HTTP 本机/IP 入口及可用 HTTPS 入口分别记证据。未实际测过的浏览器/入口不得宣称通过，也不以本功能为由改变原站已支持入口。CSS/导航需要同步当前 `.trellis/spec/frontend/directory-structure.md` 与 `identity-session.md` 对“四入口/无第五业务页”的旧现状描述；这两处与本轮用户已确认的独立页要求冲突，待行为落地时做最小范围规范更新。

## 部署与回退

新结构由增量迁移创建，先部署认识新来源的读/写代码但默认关闭专注新写入；确认全部运行实例兼容、隔离库升级/旧数据读取通过后再开放入口与写入。现有单后端 Compose 不据此宣称混合旧版滚动部署安全。写入新来源后不能直接回退到只认识两种来源的旧二进制；回退路径是关闭新入口/新写入并运行仍能读取 `FOCUS_SESSION` 的兼容版本，保留表和历史。完整备份恢复会丢失新数据，需单独授权与隔离演练，不能当成默认回退。

V15 已提交，不能因删除产品恢复功能而改写其校验和。V16 在隔离库中先将旧 `RECOVERY_REQUIRED` 行归一化到原运行/暂停阶段，并把待确认起点作为连续计时锚点，使下一次命令按新的连续计时语义补计；再删除不再使用的待确认字段与阶段约束。旧 `PENDING` 区间仅保留审计，不进入新结算。新空库直升 V16 和含 V15 会话的升级都须验证。

实施中的任一实测若迫使改变产品范围、现有记录筛选、归档行为或兼容承诺，先更新 PRD/design 并再次请求最终规划确认。
