# 四工作区真实接口浏览器验证

## 环境与范围

- Playwright Chromium，前端 `127.0.0.1:15173`、后端 `127.0.0.1:18080`，Spring `e2e` profile。
- 使用现有隔离 E2E 数据库和确定性模型替身，测试通过 `/api/e2e/reset` 重置隔离数据。
- 全部执行使用 `--retries=0`，不访问正式业务数据、不调用付费模型。
- 修改范围：`frontend/e2e/workbench.spec.ts`；业务源码由另一实现者维护。

## 测试迁移与新增

原 16 项真实 API 回归迁移到四区导航、日报/周报切换、编辑抽屉、单行项目选择器。保留分页、延迟响应、乐观锁、完成/重开、AI 重试/撤销、9 秒处理与断线恢复、来源快照、报告删除和历史版本等业务断言。

新增 3 项回归：

1. 首次访问按需挂载，记录草稿和待办筛选跨区保留，AI 完成后刷新待办仍保留筛选。
2. IME 组合输入不提交、Command/Ctrl 快捷提交防重、记录抽屉未保存取消/放弃和焦点恢复。
3. 320、390、768、1024、1440 宽度，四区及待办编辑抽屉共 25 张截图，断言页面和抽屉无横向溢出。

扩充 105 项目场景：选择数组第 80 项并实际创建关联待办，归档后通过“包含已归档”找回项目。补充日报/周报双向切换草稿保留。

## 执行记录

- 首轮 16 项：9 通过、7 失败。
- 5 项定位/文案迁移修正后针对复跑：5/5。新增 3 项及扩充项目场景：4/4。
- 两个剩余失败分别定位为：项目写成功后仍等待列表刷新而阻塞弹窗；原 WS 测试把 Vite 热更新握手误认为业务连接。源码将写入成功和列表刷新解耦；测试只等待 `/ws/events` 的 101，继续验证实时删除而非轮询。针对回归 **2/2**。
- 完整执行 `npx playwright test --retries=0`：**19/19 通过，1.1 分钟，无重试**。
- 视觉检查发现原生 dialog 默认 max-width 使 320px 抽屉留下约 38px 背景；源码补充 `max-width: 100vw`。响应式测试增加抽屉 `x=0`、宽度等于 viewport 的断言，并播种真实 API 生成的日报以验证正文/来源布局。
- 增强响应式针对执行：**1/1 通过，16.9 秒，无重试**。
- 最终 25 张截图位于 `.local-runtime/d10-ui-responsive/workbench-五个宽度四区和编辑抽屉布局无横向溢出-chromium-desktop/`。实现者与测试者分别复核 320/1440 日报及移动抽屉，正文/来源桌面并列、移动下置，抽屉全屏，无裁切和横向溢出。
- 全套 HTML/trace 保留在 `frontend/playwright-report/`、`frontend/test-results/`（忽略目录）。`git diff --check` 通过。

## 结论与限制

原 API 可以支持四区交互，测试未发现需要后端扩展的接口缺口。105 项目的第 80 项可以实际关联待办，证明前端没有 50 条截断；日报删除、冻结来源、版本锁及模型替身联调继续成立。本轮浏览器覆盖 Chromium，真实模型生成质量与 Safari/Firefox 不属于此次回归。
