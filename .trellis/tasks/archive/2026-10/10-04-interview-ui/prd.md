# AI 面试：原型复用与工作台集成

## 目标与依据

把 R1 原型内容区 HTML/CSS 直接迁入现有 React 工作台，连接账号私有简历及面试真实 API，完成创建、固定题单作答、交卷、报告、恢复、多场历史和手动删除。保留既有账号根、RetainedView、专注和原工作区行为。

上位合同是 `../10-04-ai-interview/prd.md`、`design.md` 和原始 `research/handoff/r1/requirements.md`、`acceptance.md`；本任务无损继承全部 FR-001–FR-026 和 INT-AC-001–INT-AC-026，以下只分配前端责任，不改写其含义。真实代码核验依据为父任务 `research/frontend-reuse.md`；设计视觉以交付 HTML/CSS 为来源，六张 PNG 为分组与层次参考。代码基线与原型快照不同，不能把原型演示交互当成当前产品能力。

## 范围与批准边界

P-01 仍待最终批准：第六个 retained 主工作区 `interview`（AI 面试），个人中心为账号菜单进入的 `profile` 辅助视图。此处记录拟执行方案，不记录为已批准事实。正式规划和上下文校验完成后，按父任务最终确认取得实现授权；批准前不写产品代码、不执行 HTML、不调用模型、不提交或发布。

本子任务负责前端组件、Scoped CSS、真实 API 消费、原生路由/导航接入、浏览器验收与适用前端规范回流。账号私有业务状态、简历原件耐久上传和清理、精确题单、计分、任务 fencing 由两个后端子任务负责。UI 不以本地状态或 HTTP fixture 替代这些服务端验收。

## 页面与交互要求

1. 面试中心保留原型页头、卡片、分组、状态与说明，使用真实 owner 分页（每页 5），清楚区分新建、继续、查看答卷/报告和删除。空、加载、失败、处理中状态齐全；保留 KPI 时只能来自后端完整统计。
2. 创建页没有临时简历上传/粘贴入口。无 current 时无简历选项可用，简历维护通过账号菜单的个人中心。主问题 select 包含 3–20 的每个整数，创建按钮动态显示 2N 轮。非空 JD 必须具有匹配原文/方向的成功分析才允许创建；解析失败或不匹配不静默忽略，明确移除 JD 后才能无 JD 创建。
3. 作答页显示本场固定题单、当前题、主问题/追问关系、真实进度与锁定答案。保存/保存并离开等待服务端成功；失败留在编辑上下文。空草稿合法，提交空字符串也按已提交锁定/推进；已答/未答依据submitted状态，不依据正文有无/trim。提交 pending同步防重，成功推进一次；未知结果读取确认后恢复，不盲增轮次。未保存内容用共享Dialog和beforeunload保护。
4. 报告展示完整预定轮次的原题、答案和反馈；未提交轮次明确为未作答/0，已提交空文本仍是已答，需有效评估（可真实0并具体反馈），不自动归为未作答。模型未评估明确为未评估；必要评分不完整时隐藏完整总分，答卷仍可读、可手动重试。总分只使用后端结果。查看历史不发模型POST。
5. 个人中心保持单一当前简历，编辑区与已生效摘要分开；合法文件选择后可修改其导入文本，显式保存multipart绑定不可变原件和实际编辑文本。原File解码正文与最终编辑正文分别满足20,000码点；不添加未确认的非空/最小长度门禁，空正文与无current用exists区分。普通编辑当前简历显式使用EDIT_CURRENT，按expectedVersion保留既有来源/原件关联，原件下载仍是原字节；用户显式选择粘贴替换才使用PASTE，并在操作前说明会移除旧原件关联。来源/下载入口按返回sourceKind确证。取消/验证失败/保存失败/版本冲突保留有用本地输入，放弃才恢复最后生效文本。私有原件仅通过owner后端业务读取，不显示公开/预签名URL。
6. 删除、提前交卷、放弃编辑、离开 dirty 编辑使用既有原生 Dialog；键盘/焦点/取消/busy/危险按钮遵守共享规范。短屏与窄屏全部导航、最后轮、最终按钮和分页可达。

## 现有行为约束与非目标

保留五个原工作区草稿/筛选、唯一专注控制器与音频、现有账号/401/CSRF/五秒 Toast、显式活动与后台流量规则、社区公开 profile 与附件行为。新增 route 不重建账号根，刷新列表不靠变化 key；只为当前活动编辑上下文注册离开 guard。

只迁原型内容 HTML/CSS，移除原型 shell、sidebar/topbar、全局 reset、演示 tabs/hash render/onclick、假账号/计时/样例题分数。继续使用现有 Dialog、Toast、request、Pagination 与 pinned Markdown 依赖，不新增 UI/Markdown 库，不在生产运行时读取交接包或任务目录。不新增兼容 alias、兼容层、feature flag、默认禁用门禁。语音、动态追问、简历版本库、PDF/Word、JD 文件/抓取、代码运行、公开面试、PDF 导出和模型管理 UI 均不在范围。

前端只消费 owner 业务 API，RustFS/未来阿里云切换由后端 ObjectStorage 合同负责，不向浏览器暴露凭据/provider-specific 分支。本轮不申请阿里云 API、不实现或验收 OSS、不调用付费真实模型。

## 依赖与完成条件

依赖 `../10-04-interview-resume` 的 current/version/multipart/original 合同，继而依赖 `../10-04-interview-engine` 的 JD/场次/轮次/报告/删除/retry 合同稳定及各自独立验收。P-01 和正式规划批准后可以并行迁入静态 JSX/CSS/共享组件骨架，真实联调必须沿 resume → engine → ui，不得绕过后端验收。

完成条件是本子任务 lint/build、独立浏览器流程、已受影响回归、视觉/几何证据全部通过并完成父 INT-AC 对照；阻塞与延期列入父 `research/issues.md` 最后汇总，不把未跑的真实模型/OSS/存储恢复写成通过。
