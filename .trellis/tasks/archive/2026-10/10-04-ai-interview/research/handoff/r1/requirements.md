# requirements — AI Workbench AI 面试首版

## 1. 目标

为 `ai-workbench` 增加账号隔离的文字 AI 面试能力，使已登录用户可以：
- 在个人中心维护唯一的当前 Markdown 简历；
- 新建 Java 后端 / React 前端 / Agent 开发 / 全栈四类文字面试；
- 可选粘贴 JD 以调整已选方向内的考察重点；
- 逐轮完成固定题单（每道主问题对应一条预生成追问）；
- 交卷后获得可追溯的评估结果；
- 保留并继续多场未完成面试，查看历史报告；
- 主动删除当前简历或单场面试。

成功标准是：资料、题单、答案、进度和报告均按账号隔离且可恢复；模型失败不会伪装成用户低分；历史查看不会重新触发模型；新增功能不破坏现有工作台、专注、报告、社区和账号行为。

## 2. 目标用户与场景

目标用户：`ai-workbench` 中已登录的普通用户或管理员账号。管理员在私有业务数据上与普通用户一样遵循 owner 隔离，不拥有读取其他用户面试/简历的业务绕过。

主要场景：
1. 无简历通用面试。
2. 使用个人中心当前简历的新面试。
3. 方向 + 难度 + 可选 JD 的针对性面试。
4. 中途暂存、离开后继续。
5. 多场未完成面试并存。
6. 正常交卷、提前交卷、评估失败后手动重试。
7. 历史报告查看。
8. 当前简历替换/删除、单场面试删除。

## 3. In scope

- 文字面试。
- 当前简历：`.md` 文件导入、Markdown 粘贴、保存、替换、删除。
- 四个预设方向：Java 后端、React 前端、Agent 开发、全栈。
- 难度：初级 / 中级 / 高级，默认中级。
- 主问题数量：3–20，默认 5。
- 每主问题固定 1 条预生成追问。
- 可选 JD 粘贴文本和解析；仅补充已选方向。
- 逐题草稿/提交，提交成功后不可回改。
- 提前交卷及整场计分。
- 评估、手动重试、历史报告。
- 多场未完成面试。
- 当前简历与单场面试删除。
- RustFS 复用用于导入的当前简历原文件。
- 创建时简历/JD/方向/难度/题单快照。
- 账号隔离、幂等、并发冲突和后台迟到结果 fencing。

## 4. Out of scope

- 语音面试。
- 知识库/RAG 题库面试。
- 根据用户刚提交的回答动态生成追问。
- 多份当前简历、简历版本库、旧简历选择或恢复。
- PDF / DOC / DOCX 简历。
- JD 文件上传、PDF/Word/图片/OCR、招聘网页抓取。
- 第五个“任意岗位定制”方向。
- 代码运行、在线编程判题。
- 面试日历、HR/候选人管理。
- 多模型管理 UI。
- 面试 PDF 导出。
- 社交/公开面试记录。
- 自动模型重试。
- 回收站或按天自动删除。
- 新建消息队列/独立面试微服务。
- 未经用户批准的兼容层、旧路由兼容、功能开关或默认禁用门禁。

## 5. Functional Requirements

### FR-001 当前简历唯一性
每个用户最多有一份生效的当前简历。当前简历是账号私有业务数据。

### FR-002 当前简历输入
用户可在个人中心导入 UTF-8 `.md` 文件，或直接粘贴/编辑 Markdown。保存成功后新内容才成为当前简历；失败时原已生效简历保持可用。

### FR-003 简历原文件
文件导入复用现有 RustFS/ObjectStorage 能力保存私有原件。粘贴文本无需制造伪文件。简历业务归属不得挂在社区 post 上。

### FR-004 简历删除与替换
替换成功后仅一份简历生效；无有效引用的旧原件可清理。删除当前简历后仍可做无简历通用面试；历史面试中的简历文本快照不受影响。

### FR-005 创建面试
新建面试始终创建独立会话；不因存在未完成面试或使用同一简历而自动返回旧会话。同一创建 requestId 重放不得产生重复会话。

### FR-006 创建配置
创建时必须选择：四方向之一、三档难度之一、主问题数 3–20、当前简历或无简历。默认难度中级、主问题数 5。JD 可选。

### FR-007 JD
JD 仅支持粘贴文本。用户显式触发解析；修改 JD 原文后旧解析结果失效。JD 只能调整已选方向内的考察重点，不自动改变方向、难度、题量或追问数量。

### FR-008 创建快照
创建成功时固定保存方向、难度、主问题数、当前简历文本快照（若使用）及其版本/摘要标识、JD 原文和解析结果（若使用）。之后资料变化不影响该场。

### FR-009 固定题单
每场 N 道主问题必须生成恰好 N 道主问题、每题恰好一条非空预生成追问，总轮次恰好 `2N`，追问必须有唯一有效主问题关联。进入可作答后题单不可替换。

### FR-010 题目方向
React 方向不得混入 Vue 作为默认考察框架；全栈方向以跨层业务场景为核心，不机械分配“半前端半后端”。Agent 方向只表示考察主题，不要求工作台引入 Agent/RAG/MCP 运行时。

### FR-011 暂存
当前轮答案可以暂存。暂存不锁定、不推进；刷新或离开后应恢复当前草稿。

### FR-012 提交与锁定
服务端验证 owner、会话状态、当前轮次、长度和幂等/并发版本。提交成功后保存答案、锁定本轮并推进。旧标签页、重复请求不得覆盖已锁定答案。

### FR-013 多场未完成
同一用户可有多场未完成面试；每场独立保存题单、资料快照、草稿、已提交答案和进度。新建与继续是不同操作。

### FR-014 交卷
最后一轮完成或提前交卷后答卷冻结。提前交卷前显示已答/未答轮数，并说明未答轮次按 0 分。

### FR-015 首次评估
交卷后自动触发首次评估。主问题与追问按组评估；方向、难度、简历/JD 快照必须与本场一致。

### FR-016 评估输出
每轮有效作答得到 0–100 分与具体反馈；报告可包含参考答案/要点、综合反馈、优势和改进。总分由后端固定规则计算。

### FR-017 计分
所有预定轮次等权。未作答计 0 并明确标记“未作答”。模型评估失败/缺失/错位不是用户 0 分；必要结果不完整时不得发布完整总分。

### FR-018 手动重试
JD 解析、出题、评估失败后只允许显式手动重试；不做自动模型重试。重试沿用同一场固定输入和答卷。

### FR-019 历史读取
历史列表、详情、报告只读取持久化状态/结果。刷新、查询、查看报告不得触发模型调用。

### FR-020 删除面试
用户可从任一阶段删除自己的单场面试。删除该场题单、草稿/答案、JD 原文与解析结果、评估结果、简历文本快照；不影响当前简历或其他面试。迟到后台结果不得恢复它。

### FR-021 文件清理
简历原文件仅在确认无有效引用且没有仍在处理的相关上传/替换时清理。失败不得误报物理删除成功，应保留最小不可读取清理状态供重试。

### FR-022 账号隔离
所有资料与操作绑定稳定 `userId`。ADMIN 无私有业务 owner 绕过。异步处理从持久化业务记录取得 owner。

### FR-023 输入上限
- 简历正文：20,000 Unicode 码点；
- JD：10,000 Unicode 码点；
- 每轮答案：5,000 Unicode 码点；
- `.md` 文件：1,048,576 bytes。
前后端计数语义一致；超限不静默截断。

### FR-024 模型输入安全
简历、JD 和回答是不可信数据。不得执行其中命令、脚本、代码块或远程链接；不得自动抓取外部资源。

### FR-025 任务 fencing
每次出题/评估有可验证执行权标识。重试、删除、替换执行权或处理权过期后，旧任务结果不能提交。

### FR-026 失败可恢复
进程重启或任务中断后不能永久卡在处理中；已成功持久化结果直接恢复，未确认完成任务进入明确失败/中断状态并等待手动重试。

## 6. 不得破坏的现有行为

1. 现有工作记录、待办、专注、工作汇报、项目管理五个工作区行为不变。
2. account root / RetainedView 对已访问工作区草稿和筛选状态的保留不变。
3. 专注控制器不能因进入 AI 面试或个人中心而重建、暂停或丢失。
4. 现有 session idle/activity 规则不变；后台轮询/推送不能刷新显式活动时间。
5. owner-scoped 查询规则不变；ADMIN 不获得私有业务绕过。
6. 社区公开资料、发布、私有附件的现有 API/权限/对象前缀和清理规则不变。
7. 已应用 Flyway migrations 不修改。
8. 现有日报/周报、输入处理及其删除/重试规则不因面试模块改变。
9. 不增加未经批准的兼容层或 feature flag。

## 7. Acceptance Criteria

### INT-AC-001 账号隔离
A、B、ADMIN 交叉请求他人简历、会话、答案或报告时无私有内容/状态泄露；写入不发生；所有业务只影响 owner。

### INT-AC-002 精确题单
N=3、5、20 成功创建时必须得到 6、10、40 轮；每主问题恰好一条非空追问且 parent 正确。少题、空追问、错误关联、超量结果不能进入可作答状态。

### INT-AC-003 提交后不可回改
当前轮提交成功后，重复、旧轮次、旧标签页或并发提交不能修改已锁定答案，进度只推进一次。

### INT-AC-004 暂存与响应丢失
暂存后刷新/重新进入可恢复草稿且未推进。提交响应丢失后读取服务端状态：已成功则恢复下一轮，未成功则仍本轮，不双推进。

### INT-AC-005 提前交卷
确认前显示已答/未答和未答按 0；确认后答卷冻结，未答轮次固定标记未答且不能补答。

### INT-AC-006 报告一致性
给定固定题单、答案和有效逐轮评分，总分等于“所有预定轮次得分之和 / 轮次数”；历史读取结果不变。

### INT-AC-007 系统失败不冒充低分
评估超时、坏结构、缺必要题目或题号无法可靠映射时不发布完整总分；失败轮次不写成用户 0；答卷保留可重试。

### INT-AC-008 现有工作区回归
从记录/任务/专注/报告/项目进入 AI 面试再返回，原 retained 草稿/筛选仍在；活跃专注会话不变。

### INT-AC-009 简历快照
用简历 A 创建面试1，再把 current resume 改 B；面试1继续/重试/历史始终 A，新建面试2使用 B。

### INT-AC-010 Markdown 安全
简历含链接、HTML、脚本、代码块、伪指令时只作为文本数据，不执行、不抓取、不提升为系统指令。

### INT-AC-011 个人中心简历输入
`.md` 导入与 Markdown 粘贴只在简历维护入口；面试创建页没有临时上传。导入/保存失败不覆盖旧 current resume 和编辑内容。

### INT-AC-012 RustFS 私有原件
导入原文件只能经后端 owner 鉴权访问；A/B 互相不能读取；浏览器无公开/预签名对象 URL；粘贴模式不要求文件对象。

### INT-AC-013 单一当前简历
并发保存/替换后最终至多一个 current resume 生效；冲突明确失败/刷新，不产生两份可选简历。

### INT-AC-014 创建只认当前简历
带简历创建只接受服务端 current resume 及用户确认版本；客户端伪造旧/他人 resumeId 或替代正文无效。无简历仍可建通用面试。

### INT-AC-015 方向/难度一致
创建后方向/难度冻结；出题、追问、评估一致。React 不按 Java 固定角色；初级不按高级 rubric。

### INT-AC-016 查询不触发模型
列表、详情、刷新、报告 GET、状态轮询、成功结果重复读取不新增模型请求；只有首次交卷评估和显式 retry 可调用对应模型操作。

### INT-AC-017 仅四个方向
服务端只接受 Java 后端 / React 前端 / Agent 开发 / 全栈；其他值失败。React 不默认 Vue；全栈体现跨层业务关联。

### INT-AC-018 JD 快照与失效
JD 仅文本。解析后修改任一字符，旧分析不能创建；重新解析后创建保存原文与分析快照，旧面试不受后续变化影响。

### INT-AC-019 JD 失败不静默降级
解析失败或方向不匹配时保留原文并提示；不自动换方向、不静默忽略。只有用户明确移除 JD 才按无 JD 创建。

### INT-AC-020 当前简历替换/删除
替换失败旧简历继续生效；成功后新简历唯一生效。删除 current resume 不删除历史面试快照，通用面试仍可建。

### INT-AC-021 删除面试
删除后会话从列表消失，题单/答案/JD/报告/简历快照不可正常读取；迟到任务/重放/刷新不能恢复；其他会话和 current resume 不变。

### INT-AC-022 原文件清理与备份边界
被引用或活动替换中的对象不得删；无引用对象清理失败可重试且业务不可读。在线删除不能被描述为历史备份同步删除；PostgreSQL 与 RustFS 恢复分别验证。

### INT-AC-023 输入上限
分别验证简历 20,000/20,001、JD 10,000/10,001、答案 5,000/5,001 码点和 `.md` 1,048,576/1,048,577 bytes；上限允许，上限+1 拒绝且不截断/覆盖/推进。

### INT-AC-024 中断/手动重试/fencing
任务中断、重启或处理权过期后不永久 PROCESSING；只有显式 retry 发新调用；旧 token 不能覆盖新结果或已删除状态。

### INT-AC-025 最大组合
隔离环境用 20 主问题、40 轮和最大允许输入组合验证：要么完整成功，要么明确失败；无残缺题单、伪总分或静默截断。

### INT-AC-026 多场未完成
同一用户至少两场不同配置未完成面试可分别暂存/提交并在刷新/重新登录后继续；新建第三场不改变前两场；删一场不影响其余；同一 create requestId 重放不重复。
