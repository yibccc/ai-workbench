# AI Workbench · AI 面试原型设计说明

## 仓库事实基线

- `ai-workbench`: `master@cf6ca832bdfffe13628489a99e80bbd3bbe9940a`。
- 当前工作台前端采用固定侧栏 + 顶栏 + `RetainedView`，主导航当前为工作记录、待办任务、专注、工作汇报、项目管理；本原型建议新增 `AI 面试` 工作区。
- 当前账号菜单尚无独立“个人中心”；本原型建议从账号菜单增加“个人中心”入口，简历为私有账号级资料。
- 现有紫色主操作色、白色内容卡、灰色侧栏、圆角和边框体系沿用 `frontend/src/styles.css` 的视觉语言。

## 用户已决定

1. 首版仅文字面试：预生成追问、评估、历史记录。
2. 每用户只有一份当前简历，在个人中心维护；支持导入 `.md` + 粘贴 Markdown。新建面试只能选择当前简历或无简历通用面试。
3. 创建面试时保存简历文本快照；更新当前简历只影响新面试，旧面试继续使用创建时快照。
4. 四个方向：Java 后端、React 前端、Agent 开发、全栈。
5. 可选 JD，仅粘贴文本；JD 只调整已选方向内的侧重点，不创建第五个任意方向。
6. 难度初级/中级/高级，默认中级；出题与评分使用同一档。
7. 主问题默认 5，可选 3–20；每道主问题固定一条预生成追问，总轮数为 2N。
8. 逐题提交后不可回改；暂存不锁定。提前交卷后未答轮次按 0 计入整场总分。
9. 评估失败不按 0 分；不发布完整总分，保留答卷并由用户手动重试。首次正常交卷自动触发评估。
10. 允许多场未完成面试；新建与继续分开，各场题单、快照、JD、进度独立。
11. 删除本人手动确认，无回收站、无按天自动删除；删除面试不影响当前简历。
12. 输入上限：简历正文 20,000 Unicode 码点；JD 10,000；每轮答案 5,000；`.md` 文件 1 MiB 且正文仍需满足 20,000 字符。

## 页面信息架构

### AI 面试 / 面试中心
- 新建面试 CTA 与“继续面试”严格区分。
- 每场显示：方向、难度、是否使用简历/JD、业务状态、作答进度、创建/更新时间。
- 评估失败状态不展示总分，只展示“手动重试”。
- 侧栏保留现有专注 compact 状态，AI 面试不能重建 account root / focus controller。

### 新建面试
- 方向四选一。
- 难度与主问题数。
- 简历只能选“当前简历”或“无简历”；不提供临时上传/粘贴。
- JD 只允许粘贴文本，显式点击“解析 JD”；修改原文后旧解析结果失效。
- 创建按钮明确显示总轮数，如 `创建面试 · 10 轮`。

### 作答页
- 页面显式区分主问题和对应追问。
- 当前答案可暂存；提交成功后锁定并推进一轮。
- 提交按钮旁明确“提交后不可修改”。
- 右侧显示全场轮次进度；提前交卷提示未答按 0 分。
- 页面切走/刷新后，从服务端恢复真实进度；旧标签页不得覆盖锁定答案。

### 评估报告
- 成功：总分、完成进度、综合反馈、逐轮反馈、参考答案/要点。
- 未作答：按 0 分但标记为“未作答”，不得编造技术错误。
- 系统评估失败：不发布完整总分，展示失败与手动重试。
- 查看历史只读取持久化结果，不触发新模型调用。

### 个人中心 / 当前简历
- 唯一当前简历，可导入 `.md` 到编辑器，也可直接编辑 Markdown。
- 保存完整成功后才切换 current resume；失败保留原生效版本。
- 删除当前简历不删除历史面试快照。

### 删除确认
- 删除一场面试包含题单、答案、JD 原文与解析结果、评估结果、简历文本快照。
- 不影响当前简历及其他会话。
- 后台迟到结果必须被 fencing，不能重建已删除业务对象。

## 建议接入点（尚未批准为实现路径）

- `navigation.ts`: 新增 `interview`，保持为主工作区 retained view。
- `AccountMenu.tsx`: 增加个人中心入口；不把私有简历放进社区公开 profile。
- `App.tsx`: AI 面试 retained view 与现有 records/tasks/focus/reports/projects 同属 account root；切换账号时清理该账号的请求/草稿状态。
- 建议前端 feature 边界：`features/interview/` 与 `features/profile/`；共享 HTTP 类型进入对应 `api/` 模块，不扩张根 api。

## 关键状态合同草案

- 出题：PREPARING → READY | FAILED；失败仅手动重试。
- 作答：READY / IN_PROGRESS → SUBMITTED（交卷后答卷冻结）。
- 评估：PENDING → PROCESSING → SUCCEEDED | FAILED；FAILED 不改回可作答。
- 删除：从任何状态进入业务不可读；旧 task token / lease 不得提交迟到结果。
- 简历：编辑草稿与生效 current resume 分开；创建会话校验用户确认过的简历版本，成功后复制文本快照。

## 待验证假设

- 20 道主问题 / 40 轮与最大允许输入组合，实际模型上下文、延迟与质量尚未验证。
- 任务超时、lease 长度、TaskExecutor 并发度需在隔离环境测量后确定。
- RustFS 当前应用身份是否已允许新的 resume 对象前缀，需要本地权限核验；不得直接放宽全桶管理权限。
- `ai-interview` 中可复用代码、提示词和 skill 资源受其 AGPLv3 许可约束；实际复制范围与发行/网络服务义务在冻结前需要明确。
- 现有 PostgreSQL 备份脚本未覆盖 RustFS 对象；简历原文件的备份/恢复不能被现有 DB backup 声称覆盖。
