# 子任务 PRD：前端身份体验与部署接入

父任务：`09-25-auth-isolation`。主责 FR-009/010/012、FR-013 的前端/入口回归及 `AC-ISOLATION-010`；AC 唯一定义在父任务 `prd.md`，TC 方法在父任务 `research/handoff/r1/acceptance.md`。依赖认证接口、归属 404 合同和 STOMP 协议可用。

## 目标、范围和非目标

未登录显示独立登录页；已登录用户沿用四个既有工作区。桌面侧栏底部、手机顶栏提供账号菜单（用户名、改密、退出），ADMIN 另见用户管理辅助页；管理包含列表、创建、启停、重置密码、角色修改。账号表单按已选字段，动作说明全端失效/本人数据保留。认证失效一经检测立即回登录页并显示现有 5 秒 Toast；普通 403/404、网络失败和业务错误不误报过期。换账号后旧草稿、pending ID、迟到响应与订阅不呈现/写入新身份。

部署时用应用认证取代旧 Nginx Basic Auth 和共享入口密码，保留 HTTPS 反代、Origin、WebSocket Upgrade、隐藏健康检查、Windows 本机与 Docker 使用路径。生成图只作为布局与表单视觉参考；图中搜索、铃铛、第五业务导航、常驻过期卡片均不成为需求。不增加管理搜索/分页/批量、设备页、通知中心或重做四业务页。

## 可观察验收

- `AC-UI-001～009/013`：登录、四导航、桌面/手机账号入口、ADMIN 管理辅助页、表单字段与默认 USER/确认密码均符合范围；取消不变更，窄屏可达；USER 无管理入口，直接请求仍由后端 403。见 TC-004、TC-009、TC-031/032。
- `AC-UI-010～012`：真实认证失效立即撤出业务视图，登录页的 Toast 保留 5000ms/可提前关闭/新事件重计；403、404、网络或本地校验维持原语境。见 TC-033/034。
- `AC-ISOLATION-010`：同浏览器 A 退出后 B 登录，A 的草稿、缓存、pending ID、迟到响应、订阅不能在 B 视图或保存中复现；同身份普通切页仍保持既有草稿。见 TC-035。
- `AC-DEPLOY-001/002`：正式入口无 Basic Auth 挑战、旧 `WORKBENCH_AUTH_*` 不再是访问条件；应用登录保护 API/STOMP；HTTPS/代理/Origin/健康检查边界保留。见 TC-038/040。
- `AC-REGRESSION-001` 前端部分：四工作区、分页、抽屉、焦点、未保存确认、迟到请求处理与单屏响应式合同保持。见 TC-040。

P-001 已确认仅主动操作续期：UI 中的明确点击、键盘编辑、手动业务操作应让本会话续期；15 秒兜底查询、自动重连/订阅、心跳和纯推送不得续期。即使用户只在本地编辑、没有其他业务 HTTP 请求，也应通过受保护的技术活动信号让服务端获知主动操作；不增加用户可见的活动追踪页面。实际部署库、域名、清理目标及模型凭据不在本轮规划中核实或执行。
